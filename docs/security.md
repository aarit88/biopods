# Security & Safety Architecture

BioPods enforces a defense-in-depth safety and security posture designed to prevent autonomous runaway actions.

---

## 1. Safety Guard Pipeline

Every remediation candidate generated by the planning agent must pass through the validation gate:

```
[Candidate Action Plan]
           │
           ▼
[Zod Schema Validation] ──▶ Reject malformed plans
           │
           ▼
[Namespace Check] ────────▶ Reject kube-system, kube-public, kube-node-lease
           │
           ▼
[Ceiling & Limit Check] ──▶ Reject scale > 8 replicas
           │
           ▼
[Cooldown Window] ────────▶ Reject actions on target within 15-second window
           │
           ▼
[Autonomy Gate] ──────────▶ Check risk level against cluster autonomy level
           │
           ├── [Requires Approval] ──▶ Human Approval Queue
           └── [Permitted] ──────────▶ Healing Executor
```

---

## 2. Autonomy Levels

Administrators can dynamically configure cluster autonomy levels from the BioPods Command Center:

| Level | Name | Automated Scope | Approval Required |
| :--- | :--- | :--- | :--- |
| **0** | `OBSERVE_ONLY` | Passive surveillance only | All actions |
| **1** | `RECOMMEND` | Generates diagnoses & plans | All actions |
| **2** | `AUTO_HEAL_LOW` | Pod restarts, basic recycling | Medium, High, Critical |
| **3** | `AUTO_HEAL_MEDIUM` | Pod restarts, deployment autoscaling | High, Critical |
| **4** | `FULL_AUTONOMY` | All actions except node cordoning | Critical only |

---

## 3. Human Approval Workflow

When an action requires human sign-off:
1. Incident state transitions to `WAITING_FOR_APPROVAL`.
2. Notification is emitted over WebSockets to the UI Command Center.
3. Operator inspects evidence, proposed action, blast radius, and rollback plan.
4. Operator submits approval via `POST /api/v1/incidents/:id/approve` or rejection via `POST /api/v1/incidents/:id/reject`.
5. Upon approval, the Healing Executor dispatches the action with full audit logging.

---

## 4. Authentication & RBAC

- **Password Hashing**: PBKDF2 with SHA-256 and unique per-user salt.
- **Tokens**: JWT access tokens signed with HMAC-SHA256, expiration: 2 hours.
- **Roles**:
  - `ADMIN`: Full system configuration, policy overrides, autonomy level adjustments.
  - `OPERATOR`: Manual actions dispatch, incident approvals, node mitigation.
  - `OBSERVER`: Read-only access to dashboards, topology, incidents, and audit trail.
